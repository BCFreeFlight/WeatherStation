1 · System Overview

This handbook documents a remote weather station with camera monitoring. The system connects to a WiFi network and streams both real-time weather data and a live video feed of launch activities for paragliding and other free flight.

The installation uses two ECOWITT weather stations — one at launch and one at the landing zone — which allows the atmospheric lapse rate between the two elevations to be computed.

Live results: https://bcfreeflight.com/sites/coopers

1.1 System Architecture

  • Solar power generation and battery storage
  • Two ECOWITT weather stations (launch and LZ) with WiFi connectivity
  • IP camera for visual monitoring
  • Long-range wireless bridge for data transmission
  • Stream script for live streaming to YouTube

5 · ECOWITT Weather Station Configuration

Feeding data to Weather Underground. Follow these steps to set up the ECOWITT weather stations and send live weather data.

5.1 Two Stations in This System

This installation uses two ECOWITT GW1101 stations:

StationLocationPurpose
LaunchLaunch site, alongside the camera and network gear Primary launch conditions
LZLanding zone Landing conditions, and the second data point used to compute the atmospheric lapse rate between the two elevations

Each station is a fully independent unit. Repeat every step below once per station — each one gets its own Weather Underground device registration, its own Station ID and Station Key, and its own entry in the WSView Plus app.

Do not share a Station ID
Using one Station ID for both units interleaves readings from two different elevations into a single feed, which corrupts both the launch data and the lapse rate. Record the elevation of each station accurately when you register it — the lapse rate calculation depends on it.

5.2 Register Each Station on Weather Underground

  1. Visit Weather Underground's registration page: wunderground.com/member/devices
  2. Log in or create an account if you do not have one.
  3. Click Add a New Device.
  4. Complete the required information, including location, elevation, and station details.
  5. After registration, note the Station ID and Station Key/Password.
  6. Repeat for the second station, using its own name, location, and elevation.
Record it
Write both sets of Station ID and Station Key into §11 — Credentials Record. There is a separate block for the launch station and the LZ station.

5.3 Connect Each ECOWITT Console to Wi-Fi

  1. Plug in the ECOWITT weather station and turn it on.
  2. On the console, navigate to the network settings to enable Wi-Fi.
  3. Connect your phone to the same Wi-Fi network you want the station to use.

5.4 Use the WSView Plus App

  1. Download and install the WSView Plus app (Android or iOS).
  2. Open the app and search for the weather station device.
  3. Follow the app's instructions to connect the station to your Wi-Fi.

5.5 Configure Weather Underground Uploads

  1. Within the WSView Plus app, select the weather station device.
  2. Go to Device Settings → Weather Services or Upload Settings.
  3. Select Weather Underground.
  4. Enter the Station ID and Station Key belonging to that station (from §5.2).
  5. Save the settings.
  6. Repeat for the second station, taking care to enter the matching credentials.

5.6 Confirm Data Upload

  • Return to Weather Underground's Device Management page.
  • Both stations should show as "Online" after a few minutes. Data updates typically start within 10–15 minutes.
  • If data does not appear, double-check the Station ID, Key, and network connection.
  • If one station reports the other's conditions, the Station IDs have been swapped between the two units — correct them in WSView Plus.
Troubleshooting
Consult the ECOWITT user manual or the WSView Plus app help section.

6 · PowerBeam Bridge Configuration

Configure Ubiquiti PowerBeam antennas to communicate in bridge mode, enabling transparent network traffic between two or more locations.

6.1 Prerequisites

  • Two PowerBeam (or compatible) antennas
  • Devices powered up and connected via Ethernet for initial configuration
  • Access to the web interface for each unit
  • Default login credentials (usually ubnt/ubnt, unless changed)

6.2 Step 1 — Initial Setup

  1. Connect your computer to the PowerBeam's PoE injector LAN port using an Ethernet cable.
  2. Set your computer's network IP to a static address in the 192.168.1.x range (e.g. 192.168.1.10).
  3. Open a web browser and go to http://192.168.1.20 (the default PowerBeam IP).

6.3 Step 2 — Login and Update Firmware

  1. Log in (default username and password are usually ubnt).
  2. If needed, update to the latest firmware from Ubiquiti's official site: ui.com/download

6.4 Step 3 — Configure the First PowerBeam (Access Point)

  1. On the main menu, go to Wireless:
    • Set Wireless Mode to Access Point.
    • Enter an SSID (network name) that both antennas will use.
    • Choose your Channel Width and Frequency (try automatic, or select manually for best performance).
    • Set/encrypt with a strong WPA2 password.
  2. Go to Network:
    • Set Network Mode to Bridge.
    • Assign a static IP if desired (to avoid IP conflicts later).
  3. Apply changes and reboot if prompted.

6.5 Step 4 — Configure the Second PowerBeam (Station/Client)

  1. Connect to the second antenna and log in as above.
  2. Go to Wireless:
    • Set Wireless Mode to Station.
    • Enter the SSID to match the Access Point.
    • Set Channel Width and Frequency to match the AP.
    • Enter the same WPA2 password.
  3. Go to Network:
    • Set Network Mode to Bridge.
    • Assign a different static IP, or use DHCP if your network supports it.
  4. Apply changes and reboot if prompted.

6.6 Step 5 — Align Antennas and Test Connection

  1. Physically position and align the antennas with each other for optimal signal (use the alignment tools in the web interface).
  2. Connect your main network to the AP side and the remote device/network to the Station side.
  3. Test connectivity — devices at each end should communicate seamlessly as if on the same LAN.

6.7 Tips

  • Use the UISP app (Android/iOS) for discovery and management.
  • Use surge protectors to safeguard hardware outdoors.
  • Adjust frequencies to minimize interference, especially where other wireless networks are present.

For advanced settings and troubleshooting, consult your model's user manual or visit the Ubiquiti Community Forums at community.ui.com.

7 · Reolink Camera Configuration

Setting up the Reolink IP PoE camera and obtaining the RTSP and RTMP stream URLs. The RTSP URL is what you supply to the Stream script during installation — see §8.

7.1 Camera Hardware & Initial Setup

  1. Mount the Camera — install at the desired location using the provided hardware.
  2. Connect Power & Network — use a PoE adapter or switch to provide both power and network connectivity over a single Ethernet cable.
  3. Find the Camera on Your Network — use the Reolink app (Windows/Mac/mobile) or your router's client list to note the camera's IP address.

7.2 Accessing the Camera Web Interface

  1. Open a web browser.
  2. Enter http://<IP address> (replace with the camera's assigned address).
  3. Log in using your camera credentials (set up initially via the Reolink app or web interface).

7.3 RTSP Stream

RTSP is a common protocol for streaming high-quality video with minimal latency. This is the URL the Stream script uses as its stream.rtspUrl config value.

URL format

rtsp://<username>:<password>@<IP address>/Preview_<channel number>_<stream type>
  • <username> — camera login username
  • <password> — camera login password
  • <IP address> — camera's local IP address (e.g. 192.168.1.101)
  • <channel number> — typically 0 for single-channel cameras
  • <stream type> — main for high quality, sub for lower quality/bitrate

Example

Username admin, password MySecret123, IP 192.168.1.101, main stream:

rtsp://admin:MySecret123@192.168.1.101/Preview_0_main

7.4 RTMP Stream

RTMP is typically used for pushing streams to servers (YouTube, Twitch), but Reolink cameras also expose RTMP URLs that can be pulled by a client. RTSP is preferred for this installation; RTMP is documented here as a fallback.

URL format

rtmp://<IP address>/bcs/channel<channel id>_main.bcs?channel=<channel id>&stream=0&user=<username>&password=<password>
  • <IP address> — camera's IP address
  • <channel id> — usually 0 unless you have multiple channels
  • <username> / <password> — camera login credentials

Example

rtmp://192.168.1.101/bcs/channel0_main.bcs?channel=0&stream=0&user=admin&password=MySecret123

7.5 Troubleshooting

  • Firewall issues — ensure port 554 (RTSP) and port 1935 (RTMP) are allowed through the network firewall.
  • Multiple cameras — repeat the above for each camera, adjusting the channel number.
  • Network stability — a wired Ethernet connection is recommended for best reliability.

Additional resources: support.reolink.com

Reminder
The RTSP/RTMP URLs embed the camera username and password in plain text. Do not post them publicly. Record the camera credentials in §11 rather than writing full URLs elsewhere.

8 · Live Streaming with the Stream Script

Live streaming to YouTube is handled by BC Free Flight Stream — a self-contained Python script written for this project. It proxies the RTSP camera feed to YouTube Live via ffmpeg, manages the YouTube broadcast lifecycle, handles OAuth 2.0 authentication, retries automatically on failure, and registers its own cron jobs for unattended operation.

Source and releases: github.com/BCFreeFlight/Stream

Stable broadcast URL
Once created during --install, the same YouTube URL is reused every time the stream starts and stops. That is why it is safe to embed on the website — it does not need updating each day.

8.1 Requirements

  • Linux Mint / Ubuntu-based system (the Mele mini PC at the site)
  • Python 3.8 or later
  • ffmpeg — installed automatically by --install
  • A Google Cloud project with the YouTube Data API v3 enabled
  • An RTSP-capable camera reachable from the host — see §7

All Python dependencies are self-installed by the script on first run.

8.2 Google Cloud Setup

Do this before running the installer.

  1. Go to the Google Cloud Console: console.cloud.google.com
  2. Create a new project, or select an existing one.
  3. Navigate to APIs & Services → Library.
  4. Search for YouTube Data API v3 and click Enable.
  5. Navigate to APIs & Services → Credentials.
  6. Click Create Credentials → OAuth client ID.
  7. Select Desktop app as the application type.
  8. Copy the Client ID and Client Secret — both are needed during --install. Record them in §11.
No stream key to copy
You do not need to fetch a stream key from YouTube Studio. The installer creates the broadcast and live-stream resources through the API and writes the stream URL and key into config.toml automatically.

8.3 Install

On the streaming machine, cd to the directory where the script should live and run:

curl -fLO https://github.com/BCFreeFlight/Stream/releases/latest/download/stream.py \
  && python3 stream.py --install

The interactive wizard will:

  • Prompt for Google OAuth credentials, the RTSP URL, broadcast title/privacy/category, and the cron schedule
  • Install ffmpeg and the required Python packages
  • Open a browser for Google OAuth 2.0 authorization
  • Create the YouTube broadcast and live-stream resources
  • Write config.toml and .env beside the script
  • Detect the terminal emulator and register cron jobs
  • Print the stable YouTube URL for the stream

Re-running --install is idempotent. It loads existing configuration and only prompts for values that are missing, preserving credentials, YouTube resources, and cron entries.

8.4 Commands

CommandPurpose
stream.py --startCreate a fresh broadcast and start streaming
stream.py --stopStop ffmpeg gracefully and archive the broadcast as a VOD
stream.py --recoverResume streaming if the current time is inside the daily window (used at boot)
stream.py --installRun or re-run the setup wizard
stream.py --updateBack up and upgrade to the latest release
stream.py --roll-back [version]Restore a previous version from backup/
stream.py --reinstallClean slate: uninstall, delete config, re-install
stream.py --uninstallStop the stream, archive the broadcast, remove cron entries
stream.py --set-property <key> <value>Set a config.toml value from the command line
stream.py --start --log-level debugOverride log verbosity for a single run

All commands are run as python3 stream.py … from the directory containing the script.

8.5 Scheduling

--install registers three cron entries by default, scheduled for the April–October flying season, plus an optional fourth:

JobDefault scheduleBehaviour
Start30 6 1-31 4-10 * (6:30 AM)Opens a terminal window and starts streaming
Stop25 18 1-31 4-10 * (6:25 PM)Runs headless to stop the stream
Recover@rebootRuns --recover; resumes the stream if the machine reboots inside the window
Update (optional)0 0 * * * (midnight)Runs --update; only registered when cron.autoUpdate = true

Auto-update is disabled by default so the site is never updated unattended without consent. The start job opens a single terminal window titled "BC Free Flight Stream", which closes when the stop job fires — this prevents terminal windows accumulating over the season.

8.6 Configuration

Non-secret configuration lives in config.toml beside the script. Frequently adjusted keys:

Secrets
Secrets live in .env beside the script: GOOGLE_CLIENT_SECRET, GOOGLE_REFRESH_TOKEN, GOOGLE_ACCESS_TOKEN. Never share or commit this file. The RTSP URL in config.toml also contains the camera password in plain text.

8.7 Logs

  • Location — logs/ beside the script, one file per day
  • Format — [ISO-8601-timestamp] [LEVEL] message
  • Old files are pruned on each --start according to logRetentionDays
  • At the default info level ffmpeg progress noise is hidden; use --log-level debug to see it

8.8 Troubleshooting

Run any command with --log-level debug for full detail.

Stream never goes live / status stuck inactive

  • Verify the camera URL and that the host can reach it; check the [ffmpeg] debug lines.
  • If the camera password changed, re-run --install — special characters are encoded automatically.
  • A stream key mismatch is repaired by re-running --install.

"Playback on other websites has been disabled" (embed blocked)

  • Ensure youtube.embeddable = true and run --start again.

OAuth fails or authorizes the wrong account

  • The flow always shows the account chooser — pick the correct account.
  • To switch accounts permanently, use --reinstall.

Stream didn't resume after a reboot

  • --recover only acts inside the cron.start/cron.stop window.
  • Confirm the entry exists: crontab -l | grep bcfreeflight_stream
  • Re-run --install to repair cron entries.

No terminal window opens

  • The detected terminal may be wrong: python3 stream.py --set-property terminal xterm

pip install fails (externally-managed environment)

  • PEP 668 systems fall back to --user --break-system-packages automatically. If it still fails, pre-install the dependencies or run inside a virtualenv.

For anything not covered here, see the Stream troubleshooting guide at github.com/BCFreeFlight/Stream/blob/main/docs/troubleshooting.md

9 · Appendix A — SubmitWeather API

BC Free Flight runs a Lambda-backed ingest endpoint for weather data.

Endpoint

https://api.bcfreeflight.com/SubmitWeather?uploadKey={KEY}

where {KEY} is the deviceKey associated with your device.

Format
Currently only Weather Underground querystring-formatted data is supported.

Record the device upload key in §11 — Credentials Record.

10 · Appendix B — Adding a Station to BCFreeFlight.com

To get a weather station added to bcfreeflight.com:

  1. Set up the weather station to send data to Weather Underground (§5).
  2. Submit an issue to github.com/BCFreeFlight/bcfreeflight.github.io/issues/new with the following information:
    • Weather Underground Station ID
    • Weather Underground Station Key
    • Station name and location
    • Site elevation in metres
    • Brief description of the flying site
    • Contact information (optional)

The BC Free Flight team will handle the integration and add the weather station data to the site once the submission is approved.
